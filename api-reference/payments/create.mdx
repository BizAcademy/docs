title: "Créer un paiement"
description: "Initiez une collecte ou un dépôt avec une clé d'idempotence."
openapi: "openapi.json POST /payments"
---

Envoyez une clé `Idempotency-Key` stable pour la même opération métier. Une nouvelle clé crée une nouvelle opération.

Consultez `GET /services` avant l'intégration. Si la méthode choisie indique `otp_required: true`, recueillez le code à usage unique et envoyez-le dans `payer.otp_code`. La valeur peut être omise pour les méthodes qui ne l'exigent pas. Les codes ne sont transmis qu'au fournisseur dont la configuration les attend.

Certaines méthodes, notamment Wave et Djamo, demandent au payeur de terminer le paiement sur une page externe. La passerelle peut renvoyer ce lien dans `data.provider_link` avec le statut `PENDING`. BizConnectPay le normalise dans `data.redirect_url` et renvoie le statut `REQUIRES_ACTION`. Ouvrez cette URL pour le payeur, puis vérifiez le statut final avec `GET /payment-intents/{id}` ou un webhook. `provider_reference` contient l’identifiant de transaction retourné par la passerelle et sert au rapprochement.

Pour un paiement crypto, consultez [Paiements et décaissements crypto](./crypto). Le catalogue vous indique les méthodes crypto disponibles et les cryptomonnaies acceptées.

## Djamo avec AfribaPAY

Pour une collecte Djamo, utilisez `payment_method: "djamo"` dans les pays et devises où `GET /services` retourne cette méthode. AfribaPAY documente Djamo en Côte d’Ivoire et au Sénégal en XOF. La disponibilité réelle peut évoluer : vérifiez toujours le catalogue avant de proposer la méthode.

Le payeur doit ouvrir le lien retourné et scanner le QR code avec l’application Djamo. Pour Wave comme pour Djamo, BizConnectPay expose le lien sous `redirect_url`. Présentez-le au payeur et laissez-le ouvrir la page; ne considérez pas la demande comme payée à ce stade.

La passerelle renvoie par exemple cette structure pour Djamo. Le champ `provider_link` est conservé côté serveur puis rendu dans l’API BizConnectPay sous le nom `redirect_url` :

```json Réponse de la passerelle
{
  "data": {
    "status": "PENDING",
    "transaction_id": "PIM261101012117407530900",
    "operator": "djamo",
    "country": "CI",
    "currency": "XOF",
    "provider_link": "https://p.djamo.com/payment-link/?type=payment_confirmation&chargeId=22f2dd0d-de17-4f6a-9026-b9fa1f0161ae"
  }
}
```

```json Exemple de collecte Djamo
{
  "amount": "500",
  "currency": "XOF",
  "country": "CI",
  "operation": "COLLECTION",
  "payment_method": "djamo",
  "payer": {
    "phone_number": "+2250700000000",
    "lang": "fr"
  },
  "description": "Commande 4821"
}
```

Le statut final reste à vérifier avec `GET /payment-intents/{id}` ou avec les webhooks BizConnectPay. Utilisez `provider_reference` pour le rapprochement. Le lien Djamo ne remplace pas la vérification d’un statut `COMPLETED`.

<RequestExample>
```bash cURL
curl --request POST \
  --url https://api.bizconnectpay.com/api/v1/payments \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: order-9481-collection' \
  --data '{
    "amount": "15000",
    "currency": "XAF",
    "country": "CM",
    "operation": "COLLECTION",
    "payment_method": "mtn_momo",
    "payer": {
      "phone_number": "+237671234567",
      "lang": "fr"
    },
    "description": "Paiement commande 9481",
    "metadata": {
      "client_reference": "CMD-2026-9481"
    }
  }'
```
