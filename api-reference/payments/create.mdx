Envoyez une clé `Idempotency-Key` stable pour la même opération métier. Une nouvelle clé crée une nouvelle opération.

Consultez `GET /services` avant l'intégration. Il vous indique les méthodes disponibles pour le pays, la devise et l'opération. Envoyez le code `payment_method` retourné par le catalogue. Si `otp_required` vaut `true`, recueillez le code à usage unique et envoyez-le dans `payer.otp_code`.

## Accepter une carte Visa ou Mastercard

Une application peut demander un paiement Visa/Mastercard lorsque le catalogue retourne le service `card` pour le pays `XI`, la devise `USD` et l'opération `COLLECTION`. Envoyez `XI` comme pays et utilisez le code `card` retourné par `GET /services`. Le service doit être activé dans votre compte.

Envoyez la demande avec `POST /payments` et le scope `payments.write`. `payer.phone_number` reste requis par le contrat de collecte. Le payeur saisit ses données de carte sur la page sécurisée indiquée par `redirect_url`; ne transmettez jamais de numéro de carte ni de CVV à BizConnectPay.

```bash cURL
curl --request POST \
  --url https://api.bizconnectpay.com/api/v1/payments \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: order-4821-card' \
  --data '{
    "amount": "10.00",
    "currency": "USD",
    "country": "XI",
    "operation": "COLLECTION",
    "payment_method": "card",
    "payer": {
      "phone_number": "+237690000000",
      "email": "client@example.com",
      "lang": "fr"
    },
    "description": "Commande 4821"
  }'
```

Quand une action du payeur est nécessaire, la réponse complète de `POST /payments` contient `data.redirect_url`. Ouvrez cette URL pour que le payeur finalise la transaction. `redirect_url` vaut `null` si aucune redirection n'est requise. Une réponse `201` ou un statut intermédiaire ne confirme pas le paiement : attendez `COMPLETED` avec `GET /payments/{paymentIntent}` ou votre webhook avant de livrer la commande.

Pour Djamo, utilisez la même route et le même format de demande : remplacez simplement `payment_method`, le pays et la devise par les valeurs correspondantes du catalogue, par exemple `djamo`, `CI` et `XOF`. Le payeur ouvre `redirect_url` et suit les instructions affichées pour finaliser le paiement. BizConnectPay conserve `provider_reference` pour le rapprochement; utilisez `GET /payments/{paymentIntent}` ou votre webhook pour connaître le statut final.

Pour un paiement crypto, consultez [Paiements et décaissements crypto](./crypto). Le catalogue vous indique les méthodes crypto disponibles et les cryptomonnaies acceptées.

Exemple de demande Djamo avec la même API application :

```bash cURL
curl --request POST \
  --url https://api.bizconnectpay.com/api/v1/payments \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: order-4821-djamo' \
  --data '{
    "amount": "500",
    "currency": "XOF",
    "country": "CI",
    "operation": "COLLECTION",
    "payment_method": "djamo",
    "payer": {
      "phone_number": "+2250700000000",
      "email": "client@example.com",
      "lang": "fr"
    },
    "description": "Commande 4821"
  }'
```

La méthode peut renvoyer `redirect_url`; ouvrez-la pour permettre au payeur de finaliser l'opération. Le statut final reste à vérifier avec `GET /payments/{paymentIntent}` ou avec les webhooks BizConnectPay. N'utilisez pas la redirection navigateur comme confirmation de paiement.

Pour un paiement crypto, consultez [Paiements et décaissements crypto](./crypto). Le catalogue vous indique les méthodes crypto disponibles et les cryptomonnaies acceptées.
