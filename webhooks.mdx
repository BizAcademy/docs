BizConnectPay envoie les événements à votre serveur lorsqu'un paiement lié à une application atteint un statut final. Les webhooks sont envoyés en arrière-plan. Ils complètent `GET /payment-intents/{id}` et les URL de retour du checkout.

## Configurer le webhook de votre application

1. Créez votre application dans **Développeurs** > **Applications**.
2. Ouvrez les paramètres de cette application et ajoutez une souscription webhook.
3. Saisissez une URL HTTPS accessible publiquement et choisissez les événements à recevoir, par exemple `payment.completed` et `payment.failed`.
4. Enregistrez le secret de signature affiché lors de la création. BizConnectPay ne le montre plus après cette étape.

La souscription est associée à une application précise. Pour recevoir son webhook, créez les paiements avec les identifiants de cette application. Les paiements du tableau de bord ou d'une autre application ne sont pas envoyés à cette souscription.

## Événements de paiement

Abonnez-vous à ces deux noms dans les paramètres de votre application :

- `payment.completed` : le paiement est réussi.
- `payment.failed` : le paiement a échoué.

Les noms d'événement de l'enveloppe HTTP sont respectivement `bizconnectpay.transaction.completed.v1` et `bizconnectpay.transaction.failed.v1`. Les événements ne signalent pas un paiement simplement accepté ou en cours. Pour les liens de paiement, l'application associée au lien doit avoir la souscription active.

## En-têtes et vérification de signature

Chaque tentative contient les en-têtes suivants :

| En-tête | Description |
| --- | --- |
| `X-BizConnectPay-Event` | Type d'événement, par exemple `bizconnectpay.transaction.completed.v1`. |
| `X-BizConnectPay-Event-ID` | Identifiant stable à utiliser pour dédupliquer l'événement. Il correspond à `id` dans le corps. |
| `X-BizConnectPay-Timestamp` | Horodatage Unix utilisé pour signer la requête. |
| `X-BizConnectPay-Signature` | Signature HMAC-SHA256 au format `v1=<hex>`. |

Calculez le HMAC sur le corps HTTP brut avec la chaîne `<timestamp>.<corps_brut>` et le secret de la souscription. Ne parsez pas puis ne sérialisez pas le JSON avant la vérification : les octets doivent être ceux reçus.

```js
import crypto from "node:crypto";

function isValidBizConnectPayWebhook(rawBody, headers, secret) {
  const timestamp = headers["x-bizconnectpay-timestamp"];
  const received = headers["x-bizconnectpay-signature"];
  if (typeof timestamp !== "string" || typeof received !== "string") return false;

  const expected = "v1=" + crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.${rawBody}`)
    .digest("hex");

  const expectedBytes = Buffer.from(expected);
  const receivedBytes = Buffer.from(received);
  return expectedBytes.length === receivedBytes.length &&
    crypto.timingSafeEqual(expectedBytes, receivedBytes);
}
```

## Répondre et traiter les nouvelles tentatives

Après avoir validé la signature et enregistré l'événement de façon idempotente, répondez rapidement avec n'importe quel statut HTTP `2xx`. Par exemple :

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{"received":true}
```

BizConnectPay considère toute réponse `2xx` comme livrée. Les erreurs réseau et réponses non-`2xx` sont réessayées par la file de tâches jusqu'à six tentatives, avec un délai croissant. Votre système doit donc dédupliquer avec `X-BizConnectPay-Event-ID` ou le champ `id` avant d'exécuter l'opération métier.

<Warning>
  Un webhook est une notification serveur-à-serveur, pas une redirection du navigateur. Ne marquez pas une commande comme payée sur la seule base de la page de retour : vérifiez la signature et traitez uniquement un événement `completed` valide ou confirmez le statut avec l'API.
</Warning>
